# Behaviour specs

These files describe, with `file:line` citations into the upstream source, what
the upstream uBlock Origin Lite pages do and what the new Blocker pages must do
to stay compatible with them. They were written before the React UI existed and
were used as its source of truth. They are kept because they explain *why* the
UI behaves as it does: which messages it sends, in which order, which upstream
quirks it reproduces and where it deviates on purpose.

| Spec | Covers |
|---|---|
| [messaging.md](messaging.md) | every message between the UI pages and the background, storage keys, broadcast channel |
| [popup.md](popup.md) | the toolbar popup |
| [dashboard-shell.md](dashboard-shell.md) | dashboard frame, About pane, embedded classic panes (Custom filters, Develop) |
| [settings.md](settings.md) | the Settings pane, backup and restore |

| [i18n.md](i18n.md) | localisation, string lengths, right-to-left layout |

| [container.md](container.md) | the window of the macOS container app |

## Reading the specs

**Line numbers** refer to upstream commit
`01092d95dbc7d91599a5ad017d5b98aba1118659` (the version the `upstream/`
submodule is pinned to). After an upstream update they can drift; see
[../updating-upstream.md](../updating-upstream.md).

**Platform.** The specs were written against the Safari build. Statements
marked **[SAFARI]** are Safari-specific; most of the rest applies to every
browser, because the UI pages are the same everywhere.

**Point in time.** The specs were written and re-checked while the UI was being
built. Some notes describe the state of the code at that moment, for example
"the scaffold build does not have it yet" or "status at audit time". The
current behaviour is defined by the code and its tests; where a spec and the
code disagree, re-read the cited upstream lines.

### Markers

- **VERIFIED**, **[V]**, **[H]**, **[H2]**, **[run Rn]**, **probe Pn / An**:
  observed by running code, as described in the spec's own verification
  section. Most runs used headless Chrome with a mocked `browser` object; they
  prove what the upstream page code does, not how Safari's APIs answer.
- **INFERRED**: follows from the code but was not observed.
- **UNKNOWN**: could not be determined. Do not build on it.
- **QUIRK**, "upstream quirk": upstream behaviour that looks like a defect but
  is kept for parity unless a deviation says otherwise.
- **R-n**: a requirement for the React implementation. **D-n**, **DEVIATION**:
  an intentional difference from upstream.
- **DECISION**: a choice made by the spec, not upstream behaviour.

## UI rules (`ARCHITECTURE §N`)

The specs refer to these rules by section number.

### §2 Scope

Rebuilt in React with `@openai/apps-sdk-ui`: the toolbar popup (`popup.html`);
the dashboard shell with the Settings, Filter lists and About panes
(`dashboard.html`); the window of the macOS container app (`Main.html`).

Kept as upstream code and only re-coloured through a generated
`css/default.css`: the dashboard "Custom filters" and "Develop" panes
(CodeMirror), shown inside the new dashboard through an embedded
`dashboard-classic.html`; the picker, zapper and unpicker overlays,
`report.html`, `matched-rules.html`, `strictblock.html`.

Never touched: `js/background.js`, `js/scripting/*`, rulesets, the manifest
(apart from the name), content scripts, the converter's Swift code.

### §3 Stack

React 19, TypeScript (strict), Vite with `@vitejs/plugin-react`, Tailwind 4
through `@tailwindcss/vite`, `@openai/apps-sdk-ui` (subpath imports only).
Unit tests: vitest, `@testing-library/react`, happy-dom. Browser tests:
`playwright-core` driving the installed Google Chrome (headless, throw-away
profile, no browser download). Dependencies are pinned to exact versions.

### §5 Build outputs

- `npm run build:ext` writes `ui/dist/extension/` with exactly `popup.html`,
  `dashboard.html` and `ui/**` (hashed chunks, `ui/theme-init.js`). Vite
  `base: './'`. The HTML files reference external files only: no inline
  `<script>`, no inline event handlers, no `style=""`.
- `npm run build:container` writes `ui/dist/container/` with
  `Base.lproj/Main.html`, `Script.js` (one classic script, no ES modules) and
  `Style.css`.
- `npm run build:legacy-css` writes `ui/dist/legacy/default.css`.
- `scripts/stage.mjs` builds STAGE from PRISTINE: upstream `popup.html` becomes
  `popup-classic.html`, `dashboard.html` becomes `dashboard-classic.html`,
  `ui/dist/extension/*` is copied in, `css/default.css` is replaced by the
  generated one, `log.txt` is deleted. It always starts from PRISTINE.
- `scripts/verify-stage.mjs` is the safety gate: every file outside the
  allow-list (`popup.html`, `dashboard.html`, `popup-classic.html`,
  `dashboard-classic.html`, `ui/**`, `css/default.css`, the removed `log.txt`,
  and `img/*` files that equal `assets/icons/extension/*`) must be
  byte-identical to PRISTINE; the classic pages must equal the upstream pages;
  the manifest must be unchanged; the overlay may not contain
  `cdn.openai.com`, remote font or script URLs, `eval(` or `new Function(`.
- Safari: `platforms/safari/package.sh` runs the converter, copies the
  container page over the generated `Main.html`, `Script.js`, `Style.css`,
  patches the bundle ids and signing settings into every build configuration,
  then runs `xcodebuild`.

### §6 Runtime rules for the React pages

1. **Extension CSP is `script-src 'self'`.** No inline scripts, no `eval`, no
   `new Function`, no remote code. Runtime `<style>` tags and CSSOM inline
   styles are allowed on extension pages. The container window has
   `default-src 'self'` (see `container.md` §7 for what that allows).
2. **No remote requests** from the UI: no remote fonts, images or analytics.
   The library's style files are imported one by one, leaving out
   `katex.min.css` (it references `cdn.openai.com`).
3. **Library pieces never used:** `Markdown`, `CodeBlock`, `DatePicker`,
   `DateRangePicker` (heavy dependencies) and any `Openai*` logo icon.
4. **Browser API** only through `ui/src/lib/ext.ts`
   (`globalThis.browser ?? globalThis.chrome`). Without either (harness,
   gallery, unit tests) the harness entry installs the mock from
   `ui/src/dev/mock-ext.ts`; production entries never import it.
5. **Messages** only through `ui/src/lib/bridge.ts`: one function per message,
   typed from `messaging.md`. Unlike upstream `ext.js`, the bridge does not
   swallow failures, so the UI can show an error.
6. **Behaviour parity.** For every user action the UI sends exactly the
   messages (name, payload, order) and makes exactly the browser-API calls
   (`permissions.request`, `tabs.reload`, `scripting.executeScript`, storage
   keys) that the upstream UI makes. `permissions.request` is called
   synchronously inside the user-gesture handler (no `await` before it).
7. **i18n.** All visible text comes from `browser.i18n.getMessage` through
   `t()`; upstream placeholders are `{{name}}`. Existing keys are reused; a new
   string uses `tNew('key', 'English text')` and is English-only. Layouts must
   survive strings twice as long as English and right-to-left text, so they
   use logical CSS properties.
8. **Theme.** `ui/public/ui/theme-init.js` sets `html[data-theme]` from
   `prefers-color-scheme` before the first paint and on change. Each page sets
   its own background.
9. **Popup.** Fixed width 340 px and a height that is stable from the first
   paint (a skeleton of the final size; Safari sizes the popover from the
   content). If the React popup fails to mount, it calls
   `location.replace('popup-classic.html')`.
10. **Accessibility.** Real semantics (tablist, radiogroup, labelled controls),
    visible focus, full keyboard operation, `aria-live` for asynchronous
    results, text contrast of at least 4.5:1, `prefers-reduced-motion`
    honoured.
11. **Look.** The library's default look. Level colours come from
    `--blocker-level-0..3` (none gray, basic blue, optimal green, complete
    purple). Where the library has no component, it is built from Radix
    primitives and library tokens.

### §7 Verification constraints

Automated checks never launch the Blocker app or Safari and never change
Safari or system settings: Safari behaviour is checked by hand. Browser tests
run headless Chrome against the harness pages and a local copy of PRISTINE.
