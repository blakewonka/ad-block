## 0. Summary for people in a hurry

1. Text comes from `browser.i18n.getMessage(key)` with **one argument**. No
   message in any locale uses Chrome's `$NAME$` / `placeholders` mechanism.
2. Upstream's own placeholder syntax is `{{name}}`; it is substituted at the
   call site with `String.prototype.replace`. In the popup and the three React
   dashboard panes exactly **one** key has placeholders: `perRulesetStats`
   (`{{ruleCount}}`, `{{filterCount}}`).
3. Four keys contain inline HTML (`userScriptsInfo`, `supportS3P1`,
   `supportS6P1S1`, `supportS6Checkbox1`). Only `userScriptsInfo` is in React
   scope, and on Safari the block that shows it is hidden.
4. RTL: upstream sets `body[dir]` to `rtl` when `getMessage('@@ui_locale')` is
   exactly one of `ar he fa ps ur`, otherwise `ltr`. It never sets `lang`.
5. Numbers: `value.toLocaleString()` with no argument. No plural handling.
6. All 71 locales have all 116 keys. Two in-scope strings are empty in `ml`
   (`aboutContributors`, `aboutTranslations`). 11 in-scope messages carry stray
   leading or trailing whitespace or newlines.
7. 22 of the 63 in-scope keys have a translation more than 2x the English
   length (worst: `settingsBackupRestoreLabel`, 6.7x). Use the per-key maxima in
   section 3, not the "2x English" rule of thumb.
8. The four mode names are stored in lower case (`no filtering`, `basic`,
   `optimal`, `complete`). Upstream changes their case with CSS: lower case in
   the popup, capitalised in the Settings cards (section 2.1).
9. There is **no** key for Cancel, OK, Close (alone), Yes, No, Loading, Error,
   Search, Remove, Undo or Copy. Upstream avoids them (native `confirm()`,
   icon-only buttons).
10. The localisation layer sends no runtime message and uses no storage key
    (section 1.8). Which strings are on screen is decided by message replies,
    the `BroadcastChannel('uBOL')` listener and `disabledFeatures`
    (sections 1.8, 1.9); the UI language also decides which lists the
    background treats as defaults (section 1.8).
11. Filter lists are sorted by ruleset id, not by the displayed name, and
    search ignores the localised group headings (section 1.7).
12. The container window has no `browser.i18n`; its text is fixed English
    (section 1.11). Some library components carry English defaults that must
    be overridden (section 5.1 item 11).
13. Section 7 is the parity checklist for i18n.

## 1. How upstream resolves strings

### 1.1 The API object

- `i18n.js:24-28` picks the API object: `self.browser.i18n` when `self.browser`
  is an `Object` and not an `Element`, else `self.chrome.i18n`.
- `i18n.js:30`: `const i18n$ = (...args) => i18n.getMessage(...args);`
  Every caller passes exactly one argument (the key), e.g.
  `i18n$('popupNoWebsite')` (`EXT/js/popup.js:354`).
- `EXT/js/ext.js:26-27` exports the same object by another route:
  `export const browser = webext; export const i18n = browser.i18n;`.
  `EXT/js/settings.js:22,186` uses that one:
  `self.confirm(i18n.getMessage('resetToDefaultConfirm'))`.
- `i18n.js` is loaded as a module by both pages (`EXT/popup.html:62`,
  `EXT/dashboard.html:294`). On evaluation, unless
  `document.title === 'uBlock Origin Background Page'` (`i18n.js:34-36`), it
  (a) sets `body[dir]` (`i18n.js:39-44`, section 2), (b) attaches helper
  functions to the `i18n` object and (c) runs `i18n.render()` once over the
  whole document (`i18n.js:346`).
- Cloned `<template>` content is localised again on demand:
  `nodeFromTemplate()` calls `i18n.render(node)` (`EXT/js/dashboard.js:70-79`).
  The classic panes do the same for their editor panels
  (`EXT/js/develop.js:247`, `EXT/js/filter-editor.js:365`,
  `EXT/js/rw-dnr-editor.js:305`).
- Document titles are localised by the same pass: `<title data-i18n="extName">`
  (`EXT/popup.html:13`) and `<title data-i18n="dashboardName">`
  (`EXT/dashboard.html:7`).

**Safari:** `self.browser` exists, so `self.browser.i18n` is used. The Safari
build replaces `js/ext-compat.js` with `SAFARI/ext-compat.js`, whose line 24 is
`export const webext = self.browser;` (generic build: `self.browser || self.chrome`,
`EXT/js/ext-compat.js:24`). No other difference in string resolution code.

  `"name": "__MSG_extName__"`; `:287` `"description": "__MSG_extShortDesc__"`;
  `:21` and `:24` command descriptions `__MSG_zapperTipEnter__`,
  `__MSG_pickerTipEnter__`; `:313` `"short_name": "Blocker"` (not localised).
- 71 locale folders: `ar az be bg bn br_FR bs ca cs cv cy da de el en en_GB eo

  mr ms nb nl oc pa pl pt_BR pt_PT ro ru si sk sl so sq sr sv sw ta te th tr uk
  ur vi zh_CN zh_TW`. There is no bare `pt`, `zh`, `br` or `no` folder.

  Each entry is `{ "message": string, "description": string }`. No entry has a
  `placeholders` member and no message contains `$NAME$`, `$1` or `$$`.

  `eu:completeFilteringModeDescription` (leading and trailing `\n`),
  `ro:completeFilteringModeDescription` (trailing `\n`). The other 6 are on

  `fil:supportS6H`, `ka:supportS6Select1Option4`, `tr:supportS6Select1Option5`,

**Safari differences in the store** (`PRISTINE` versus `EXT/_locales`):

### 1.3 The DOM pass: `i18n.render(context)` (`i18n.js:189-277`)

The React pages do not run this pass, but they must reproduce its results.

| Attribute on the element | Lines | What upstream does |
|---|---|---|
| `data-i18n="key"` | 193-243 | `text = getMessage(key)`; falsy: skip (element keeps its `_` placeholder). No `{{` in text: `safeTextToDOM(text, elem)` (section 1.5). With `{{`: "selector placeholder" mode (section 1.4 b). |
| `data-i18n-title="key"` | 245-249 | `title` attribute = entity-expanded message; falsy: skip. |
| `aria-label="key"` (every element that has an `aria-label`) | 251-255 | The attribute's current value is used as the key; replaced by the entity-expanded message when non-empty, otherwise left as the raw key string. |
| `placeholder="key"` (every element that has a `placeholder`) | 257-261 | Same idea; replaced when the message is not `''`. No entity expansion. |
| `data-i18n-tip="key"` | 263-271 | Sets `data-tip` (no empty-message skip). Not used by any MV3 page. |
| `data-i18n-label="key"` | 273-276 | Sets the `label` attribute **even when the message is `''`** (no skip, unlike the four rows above). Used on one `<optgroup>`, `EXT/dashboard.html:157` (classic Develop pane). |

The six passes run in the order of the table, each over `root.querySelectorAll`
of the whole document (or of the cloned template, section 1.1). Only these
attributes are localised: there is no pass for `alt`, `value` or `<option label>`
other than `data-i18n-label`, which is why `alt="uBO Lite"` stays English
(section 1.7).

`safeTextToDOM` fast path (`i18n.js:109-126`, text without `<`): creates a text
node from the entity-expanded text; if the element has a child text node whose
value is exactly `_` it is replaced, otherwise the new node is appended. (The
guard at `i18n.js:111` reads `parent.childCount`, which is not a DOM property,
so the scan always runs; the result is as intended.) This is why upstream markup
such as `<label id="autoReload" data-i18n="autoReloadLabel"><span class="input checkbox">…</span>_</label>`
(`EXT/dashboard.html:97`) ends up with the text after the checkbox.

### 1.4 Placeholders

Four mechanisms exist; only (c) is exercised by the popup and the React
dashboard panes.

a. `i18n.safeTemplateToDOM(id, dict, parent)` (`i18n.js:154-186`): replaces
   `/\{\{\w+\}\}/g` with `dict[name]` after escaping `<` and `>` to `&lt;` /
   `&gt;` (`i18n.js:177-178`); a name missing from `dict` is replaced by the
   bare name (`i18n.js:180`). **Not called anywhere in `EXT/`.**

b. Selector placeholders inside `render()` (`i18n.js:200-243`): for a
   `data-i18n` message containing `{{x}}`, the existing child element matching
   `.x` (or `x` as a selector) is moved to that position. **No key used through
   `data-i18n`, `aria-label` or `placeholder` contains `{{` in any locale**, so
   this never triggers.

c. Call-site replacement with `String.prototype.replace(string, string)`:

   | Key | Placeholders | Call site | Value |
   |---|---|---|---|
   | `perRulesetStats` | `{{ruleCount}}`, `{{filterCount}}` | `EXT/js/filter-lists.js:56-58` (header total) and `:141` + `:164-166` (per-list `title` tooltip) | `renderNumber(n)` = `n.toLocaleString()` (`:36-38`) |
   | `dnrRulesCountInfo` | `{count}` (**single braces**) | `EXT/js/rw-dnr-editor.js:307-308`, `EXT/js/ro-dnr-editor.js:67-68` | `(count \|\| 0).toLocaleString()`; classic Develop pane; `zh_CN` lacks the placeholder, so no number is shown there |

   `replace` with a string pattern replaces the first occurrence only and
   interprets `$&`, `$1`, `$$` in the replacement. In `perRulesetStats` each
   placeholder occurs exactly once in all 71 locales and the values are
   formatted numbers, so a global, function-based replacement is equivalent.
   Word order differs by locale (for example `be`: `Правілы (колькасць:
   {{ruleCount}}), якія … (колькасць: {{filterCount}})`), so never build the
   sentence by concatenation.

d. Element insertion on the classic strict-block page:
   `fragmentFromTemplate(template, placeholder, text, details)`
   (`EXT/js/strictblock.js:85-106`) finds the placeholder with `indexOf`,
   and puts a new element (`details.tag`, with `details.attributes`) holding
   the value at that position; when the placeholder is absent the message is
   appended unchanged and the value is not shown.

   | Key | Placeholder | Call site | Inserted element |
   |---|---|---|---|
   | `strictblockReasonSentence1` | `{{listname}}` (present in all 71 locales) | `EXT/js/strictblock.js:247-251` | `<q>` with the ruleset name |
   | `strictblockRedirectSentence1` | `{{url}}` (absent in `az`) | `EXT/js/strictblock.js:287-291` | `<a href=finalURL class="code">` |

   Out of React scope; listed so that nobody mistakes `{{listname}}` and
   `{{url}}` for keys the React `t()` must fill.

Dynamic key names (computed, so a text search for the key finds nothing):

- `` i18n$(`filteringMode${level}Name`) `` with `level` 0..3
  (`EXT/js/popup.js:49-52`, `:89-92`, `:129-132`, `:201-203`).
- `` i18n$(`3pGroup${nodeid.charAt(0).toUpperCase()}${nodeid.slice(1)}`) ``
  (`EXT/js/filter-lists.js:293`) for `nodeid` in `default ads privacy malware
  annoyances misc regions imported` (`:240-283`), giving `3pGroupDefault`,
  `3pGroupAds`, `3pGroupPrivacy`, `3pGroupMalware`, `3pGroupAnnoyances`,
  `3pGroupMisc`, `3pGroupRegions`, `3pGroupImported`.

### 1.5 The restricted-HTML sanitiser (`i18n.js:46-152`)

Applied to `data-i18n` text only (never to `title`, `aria-label`,
`placeholder`, nor to strings read with `i18n$()` and assigned through
`textContent` or `title`).

- Text without `<`: plain text node. Entity expansion (`i18n.js:64-85`) covers
  exactly `&shy; &ldquo; &rdquo; &lsquo; &rsquo; &lt; &gt;` (regex
  `/&[a-z]+;/g`); any other entity stays literal.
- Text with `<` ("slow path", `i18n.js:128-151`):
  1. `text.replace(/^<p>|<\/p>/g, '').replace(/<p>/g, '\n\n')` (legacy; no
     shipped message has `<p>`).
  2. Parsed with `new DOMParser().parseFromString(text, 'text/html')`.
  3. Each top-level node of the parsed `body`: text nodes are appended;
     elements go through `sanitizeElement`; anything else (comments) is dropped.
- `sanitizeElement(node)` (`i18n.js:91-103`):
  - **Allowed tags (exact set, `i18n.js:54-62`): `a`, `b`, `code`, `em`, `i`,
    `span`, `u`.** An element with any other tag is removed **together with its
    subtree** (`i18n.js:92`, `:97-99`, `:141`). The comment at `i18n.js:46-48`
    says "rendered as plain text" and omits `u`; the code is what counts.
  - **Attributes: only `style` is removed (`i18n.js:93`). Every other attribute
    survives** (`href`, `class`, `id`, `title`, `data-*`, even `on*`). The
    comment at `i18n.js:49-50` ("For `<a>`, only href … MUST starts with
    `https://`") describes a rule the code does **not** enforce. Inline event
    handlers are neutralised only by the extension CSP.
  - Applied recursively to element children.
- The slow path appends; it does not replace the `_` placeholder text node.
- Links: `EXT/js/dashboard.js:40` runs `dom.attr('a', 'target', '_blank')` once
  at load for anchors present at that moment.

(`PRISTINE/rulesets/ruleset-details.json`, checked), so the key is the
**ruleset id** for a list and the raw `parent` text for a sub-group. Note that
`\p{Emoji}` also matches the ASCII digits, `#` and `*`, so `rus-0` and `rus-1`
both sort as `rus-`. Because the collation is the page's default locale (U5),
the order can differ by language; `docs/specs/filter-lists.md` section 3.4 has
the full order and the `cs`/`sk` difference. The React pane must sort by the
same key, never by `t()` output or `ruleset.name`.

Search (`EXT/js/filter-lists.js:392-419`) matches a case-insensitive
(`'i'` flag, locale-independent case folding) escaped regex against
`[ruleset.name, nodeid, group, tags].join(' ')`, i.e. untranslated data only.
Localised group headings (`3pGroup*`) are not searched: typing the German
heading `Werbung` finds nothing, typing `ads` finds the `ads` group's list.
This is the upstream behaviour to keep.

### 1.8 Runtime messages

The localisation layer itself sends **no** `runtime.sendMessage` payload,
uses no storage key and listens to no event. Its only browser API calls are
`browser.i18n.getMessage(key)` (one argument). In the background only,
`i18n.getUILanguage()` (`EXT/js/ruleset-manager.js:452`) is added to the
primary subtags of `navigator.languages` (`:449-451`; `dropCountry` splits on
`-` only, `:441-445`) to choose the language-specific default lists
(`ruleset.lang` matched by `\b(lang|…)\b`, `:454-456`, `:471-476`). That set
is returned as `rulesets` by `{ what: 'getDefaultConfig' }`
(`EXT/js/background.js:390-400`), which the UI uses for Backup (diff against
defaults, `EXT/js/backup-restore.js:41-70`), Reset (`:93`) and the
troubleshooting `+id`/`-id` list (`EXT/js/troubleshooting.js:137-147`). So
the **UI language changes which lists "Reset to default settings" enables**;
the React UI gets this for free as long as it uses the `getDefaultConfig`
response and never hard-codes a default list set.

are in `docs/specs/messaging.md`):

- `sendMessage` swallows errors and resolves `undefined`

  `setFilteringMode` makes `actualLevel !== afterLevel` true, so
  `setFilteringMode(undefined)` runs (`EXT/js/popup.js:93-100`) and looks up
  `filteringModeundefinedName`, a key that does not exist: the caption under
  the slider becomes empty (Chrome returns `''`; Safari, U3). The React popup
  must not reproduce this: the bridge throws (ARCHITECTURE section 6.5)
  and the UI keeps the last confirmed level name and shows an error.
- If `init()` throws (for example `tabs.query` rejects), `tryInit` swallows it
  (`EXT/js/popup.js:356`): neither `body.nodata` nor `popupNoWebsite` is set,
  the hostname line keeps its empty markup and the mode controls stay visible
  with the markup default (`data-level` unset, caption `_`). Only a `false`
  return shows `popupNoWebsite` (`:352-355`).
- A falsy `getOptionsPageData` reply returns early (`EXT/js/settings.js:332`):
  `body.loading` is never removed and the dashboard stays invisible
  (`EXT/css/settings.css:14-16`).

## 2. RTL handling and the `lang` attribute

### 2.1 What upstream does

```js
// i18n.js:38-44
document.body.setAttribute(
    'dir',
    ['ar', 'he', 'fa', 'ps', 'ur'].indexOf(i18n$('@@ui_locale')) !== -1
        ? 'rtl'
        : 'ltr'
);
```

- Target element: `<body>` (not `<html>`). Always sets an explicit value.
- Test: **exact string match** of the predefined message `@@ui_locale` against
  the five codes. A region-qualified value such as `ar_SA` or `fa-IR` would not
  match and the page would be `ltr`.
- Shipped RTL locales: `ar`, `fa`, `he`, `ur`. `ps` is in the list but has no
  locale folder, so if `@@ui_locale` reports `ps` (see U1, U2) a Pashto UI
  gets English text in an RTL layout.
- **`lang` is never set**: `<html>` has no `lang` attribute
  (`EXT/popup.html:2`, `EXT/dashboard.html:2`) and no script sets one.

Everything upstream keys off `[dir="rtl"]`:

| Behaviour | Citation |
|---|---|
| Mode slider drag: computed level is mirrored, `level = 3 - level`, when `body[dir="rtl"]` | `EXT/js/popup.js:124-126` |
| Mode slider geometry: level 0 sits at the right edge, thumb offsets use `right:` | `EXT/css/filtering-mode.css:74-92` |
| Arrow between current and hovered mode name: `'\2002\2192\2002'` (→) in LTR, `'\2002\2190\2002'` (←) in RTL | `EXT/css/popup.css:126-131` |
| Icon + label buttons swap the padding side | `common.css:147-154` |
| Legend indent, list nesting indent, the gap between items of a filter-list row (checkbox, count, expander), the popup tool-menu label indent and the About sub-lists use `margin-inline-start` | `EXT/css/settings.css:26-30`, `:161-163`, `:183-185`; `EXT/css/popup.css:152-157`; `common.css:323-327` |

### 2.2 What the React pages must do

1. Compute direction from the **primary language subtag** of `@@ui_locale`
   (split on `-` or `_`, lower-case) against upstream's list
   `ar he fa ps ur`. This equals upstream whenever `@@ui_locale` is a bare
   language code and is more robust when it is not (see UNKNOWN U1).
2. Set `dir` on `<html>` (so portals inherit it) **and** on `<body>` (upstream
   parity), before the first React render.
3. Set `lang` on `<html>` (upstream does not; this is an intentional addition
   for screen readers, hyphenation and CJK glyph selection): the BCP 47 form of
   `@@ui_locale` (`_` → `-`) when its primary language has a shipped locale,
   else `en`. Known imprecision: `cv` ships as 100% English text.
4. Radix primitives take direction from React context (or a `dir` prop), not
   from the DOM. Wrap each app root in the Radix direction provider with the
   computed `dir`, otherwise arrow-key navigation in tabs, radio groups and
   sliders is not mirrored. The installed `radix-ui` 1.6.7 exports it as
   `import { Direction } from 'radix-ui'` → `<Direction.Provider dir={dir}>`
   (`node_modules/radix-ui/dist/index.d.ts:19-20`,
   `node_modules/@radix-ui/react-direction/dist/index.d.ts`). Whether the
   components of `@openai/apps-sdk-ui` honour it is not verified here.
5. Mode order: level 0 is at the inline-start edge in both directions (in RTL
   that is the right edge, as upstream). Pointer maths that use physical `x`
   must mirror exactly as `EXT/js/popup.js:124-126` does.
6. Direction-sensitive glyphs (the "current → hovered" arrow) flip in RTL.
7. Keep these LTR regardless of page direction, each as an isolated run
   (`dir="ltr"` or `<bdi>`): hostnames and URLs, the version string, the
   troubleshooting text, `<code>` content, ruleset names (mostly Latin with
   flag emoji), the `n/m` counter. Upstream does this only for the
   troubleshooting block; the others are recommendations, not parity
   requirements.
8. The embedded `dashboard-classic.html` runs upstream `i18n.js` and applies
   upstream's exact-match rule on its own `<body>`. If Safari reports a
   region-qualified `@@ui_locale`, the classic frame would be LTR inside an RTL
   shell. Check once on a real RTL system (see U1).

## 3. Keys per surface, with English text and longest translation

How to read the tables:

- All lengths are measured on the **trimmed** message.
- "Where upstream uses it": file and line under `EXT/` (see the abbreviation
  note at the top). Unless something else is stated the mechanism is a
  `data-i18n` attribute, i.e. element text.
- "English text (length)": the `en` message, then its UTF-16 length. `⏎` stands
  for a newline character in the message.
- "Longest translation by UTF-16 length": the locale whose message has the
  largest `String.prototype.length`, shown as locale, length, (grapheme
  clusters counted with `Intl.Segmenter`), text. When several locales tie, the
  others are named or counted; the text shown is English if English is among
  them, otherwise the tied text with the most grapheme clusters (first in
  alphabetical order if that ties too).
- "Most grapheme clusters": Indic, Sinhala and Thai scripts inflate the UTF-16
  length (combining marks count as characters), so when the locale with the
  most grapheme clusters is a different one it is shown too: locale, clusters,
  (UTF-16 length), text. For Latin, Cyrillic and Greek text this column is the
  better guide to rendered width.
- "longest ÷ English": longest UTF-16 length divided by the English length.
- "(contains U+….)" after a text flags invisible characters that are part of
  that text (section 1.2).
- Neither measure is a pixel width. Weighting CJK and Hangul characters as two
  cells changes the winner for exactly one of the 116 keys: `aboutPageName`,
  where `ja` `uBO Lite について` (13 characters, about 17 cells) is wider than
  the 16-character `hy` text.

## 5. Recommended TypeScript API for `src/lib/i18n.tsx`

### 5.1 Contract

```ts
/** Plain text for `key`. '' when the key is missing or empty in the active
 *  locale. Result is trimmed; allowed tags are stripped (their text is kept);
 *  `{{name}}` placeholders are replaced from `subs`, unknown ones stay as-is. */
export function t(key: string, subs?: Record<string, string | number>): string;

/** For a string that exists in no locale file. Returns `english` (with the
 *  same substitution rules) unless the browser has a message for `key`. */
export function tNew(key: string, english: string, subs?: Record<string, string | number>): string;

/** Rich rendering: allowed inline tags become React elements, everything else
 *  is text. Never uses dangerouslySetInnerHTML or DOMParser. `subs` values may
 *  be React nodes. Renders nothing when the message is ''. */
export function T(props: { k: string; subs?: Record<string, React.ReactNode>; fallback?: string }): React.ReactElement | null;

/** Sets <html dir>, <html lang> and <body dir>. Call once per entry, before
 *  createRoot().render(). Returns what it applied. */
export function initDocumentLocale(doc?: Document): LocaleInfo;
export function getLocaleInfo(): LocaleInfo;
export interface LocaleInfo { uiLocale: string; language: string; dir: 'ltr' | 'rtl'; lang: string }

/** n.toLocaleString() — the one place numbers are formatted. */
export function formatNumber(n: number): string;

export const modeNameKey: (level: 0 | 1 | 2 | 3) => string;   // 'filteringMode<level>Name'
export const groupNameKey: (groupId: string) => string;       // '3pGroup<Capitalised>'

/** Pure parser, exported for unit tests. */
export function parseRich(message: string): RichNode[];
```

Rules that make this safe and equivalent to upstream:

1. **Lookup** goes through the `i18n` object exposed by `src/lib/ext.ts`
   (`getMessage(key)` with one argument), wrapped in `try/catch`; a non-string
   or empty result is `''`.
2. **Trim** leading and trailing whitespace (`String.prototype.trim`).
   Deviation from upstream, which does not trim; it matters for 17 shipped
   messages, 11 of them in React scope (section 1.2). The untrimmed form is
   invisible in normal HTML text flow but not in `aria-label`, `title`,
   `placeholder` or `white-space: pre-line` blocks. Inner newlines are kept.
   `t()` does not change letter case; case transforms stay in CSS
   (section 2.1).
3. **Substitution**: `/\{\{(\w+)\}\}/g`, replaced through a function (never a
   replacement string, so `$` in a value is inert). Values are inserted as
   text; in `<T>` a string value becomes a text node, which is the equivalent
   of upstream's `<`/`>` escaping (`i18n.js:177-178`). A placeholder with no
   value stays verbatim (`{{name}}`), as with upstream's call-site `replace`.
   Single-brace `{count}` is not a placeholder for this API.
4. **Tags** (`<T>` only): exactly `a b code em i span u`, case-insensitive.
   - Attributes are all dropped except `href` on `<a>`, kept only when it
     matches `/^https:\/\/[^\s"'<>]+$/`; such links render with
     `target="_blank" rel="noopener noreferrer"`. An `<a>` without a valid
     `href` renders its children with no link. This is **stricter than the
     upstream code** (which keeps every attribute but `style`) and equal to the
     rule stated in the upstream comment (`i18n.js:46-52`).
   - A closing tag with no matching opener is ignored; tags left open are
     closed at the end of the string. This gives the same visible result as the
     HTML parser upstream uses for the two malformed shipped strings
     (`he` and `zh_CN` `userScriptsInfo`). A closing tag that closes an outer
     element also closes the inner ones (`<b>x <i>y</b> z` gives italic only
     for `y`); the HTML parser would reopen `<i>` for ` z` (formatting-element
     reconstruction). No shipped message is mis-nested this way.
   - A tag that is not in the allowed set is dropped but the text inside it is
     kept as plain text. Upstream removes the whole subtree; no shipped message
     contains such a tag, so the difference cannot be observed today.
   - A `<` that does not start a tag stays literal text.
5. **Entities**: the seven upstream entities (`&shy; &ldquo; &rdquo; &lsquo;
   &rsquo; &lt; &gt;`) are decoded in text runs after tag parsing; others stay
   literal. No shipped message contains `&`.
6. `t()` on an HTML-bearing key returns the text without tags, so it is always
   safe for attributes. For element text, `<T k="…"/>` and `{t('…')}` give the
   same characters whenever the message has no tags (checked for all 8236
   messages), newlines included, so `<T>` may be used for every paragraph-like
   string (descriptions, legends) as `docs/specs/settings.md` asks.
7. **Empty results.** `t()` returns `''` in the cases where upstream skips the
   element (`i18n.js:195`, `:247`, `:253`, `:259`): there the element keeps
   whatever the markup had, i.e. nothing, a literal `_`, or the raw key in
   `aria-label`. Components must not render an interactive element or heading
   with an empty name. For the two known cases (`ml`: `aboutContributors`,
   `aboutTranslations`) use `tNew('aboutContributors', 'Contributors')` and
   `tNew('aboutTranslations', 'Translations')`, which return the translation
   when there is one and English otherwise.
8. **New strings.** `_locales/**` is not on the stage allow-list
   (ARCHITECTURE section 5), so a `tNew` key can never be added to the
   locale files and always shows English. Use camelCase keys, document every one,
   and prefer reusing a key: `saveButton` (Save), `revertButton`
   (Revert), `addButton` (Add), `exportButton` (Export…), `backupButton`,
   `restoreButton`, `resetToDefaultButton`, `popupMoreButton` (More),
   `popupLessButton` (Less), `strictblockBack` (Go back), `strictblockClose`
   (Close this window), `strictblockProceed` (Proceed), `pickerPick`,
   `pickerPreview`, `pickerCreate`, `3pGroupDefault` (Default),
   `findListsPlaceholder` (Find lists). There is no key for Cancel / OK /
   Close / Yes / No / Loading / Error / Search / Remove / Undo / Copy.
9. No caching, context or re-render logic is needed: the locale cannot change
   while a page is open and `getMessage` is synchronous.
10. Production entries must not import locale JSON; the harness mock
    (`src/dev/mock-ext.ts`) supplies `getMessage` and must return `''` for
    unknown keys and a locale code for `@@ui_locale`.
11. **Library components with built-in English text.** These defaults of
    `@openai/apps-sdk-ui` 0.2.2 would show English in every locale unless the
    caller passes a value (found by scanning
    `node_modules/@openai/apps-sdk-ui/dist/es/components/**/*.js`):
    `Select` `placeholder = "Select..."`, `loadingPlaceholder = "Loading..."`,
    `searchEmptyMessage = "No results found."`; `SelectControl` clear button
    `aria-label "Clear current value"`; `Slider` `resetTooltip = "Reset to
    default"`; `TagInput` remove button `aria-label "Remove item"`. Upstream
    has none of these controls in React scope; a component that uses one
    must pass a `t()`/`tNew()` value for every such prop (for the Slider,
    `resetToDefaultButton` is not a fit: it says "Reset to default
    settings…"). No other English literal was found in the component code.
12. **Native dialogs.** Upstream asks for the reset confirmation with
    `self.confirm(i18n.getMessage('resetToDefaultConfirm'))`
    (`EXT/js/settings.js:186`); the dialog buttons are drawn by the browser,
    not by the extension (that Safari localises them is expected but not
    verified here). A custom in-page dialog needs Cancel/OK labels, for
    which no key exists (item 8), so it adds two English-only strings in all
    71 locales; document them if that route is taken.

  const stack: { tag: string; children: RichNode[] }[] = [{ tag: '', children: root }];
  let last = 0;
  for (const m of message.matchAll(TAG_RE)) {
    pushText(stack[stack.length - 1].children, message.slice(last, m.index));
    last = m.index + m[0].length;
    const tag = m[2].toLowerCase();
    if (!ALLOWED_TAGS.has(tag)) continue;            // tag token dropped, inner text kept
    if (m[1] === '/') {
      let i = stack.length - 1;
      while (i > 0 && stack[i].tag !== tag) i -= 1;
      if (i > 0) stack.length = i;                   // unmatched close tags are ignored
      continue;
    }
    const node: RichNode = { type: 'tag', tag: tag as RichTag, children: [] };
    if (tag === 'a') {
      const h = HREF_RE.exec(m[3]);
      const href = h === null ? undefined : (h[1] ?? h[2]);
      if (href !== undefined && SAFE_HREF_RE.test(href)) node.href = href;
    }
    stack[stack.length - 1].children.push(node);
    stack.push({ tag, children: node.children });
  }
  pushText(stack[stack.length - 1].children, message.slice(last));
  return root;                                       // tags left open are closed implicitly
}

function plain(nodes: readonly RichNode[], subs?: Subs): string {
  let out = '';
  for (const n of nodes) {
    if (n.type === 'text') out += n.text;
    else if (n.type === 'slot') out += subs !== undefined && Object.hasOwn(subs, n.name) ? String(subs[n.name]) : `{{${n.name}}}`;
    else out += plain(n.children, subs);
  }
  return out;
}

function rawMessage(key: string): string {
  try {
    const s = i18n.getMessage(key);
    return typeof s === 'string' ? s.trim() : '';
  } catch {
    return '';
  }
}

export function t(key: string, subs?: Subs): string {
  const raw = rawMessage(key);
  return raw === '' ? '' : plain(parseRich(raw), subs);
}

export function tNew(key: string, english: string, subs?: Subs): string {
  return plain(parseRich(rawMessage(key) || english), subs);
}

export function formatNumber(n: number): string {
  return n.toLocaleString();                         // parity: filter-lists.js:36-38
}

export const modeNameKey = (level: 0 | 1 | 2 | 3): string => `filteringMode${level}Name`;
export const groupNameKey = (groupId: string): string =>
  `3pGroup${groupId.charAt(0).toUpperCase()}${groupId.slice(1)}`;  // filter-lists.js:293

export interface TProps {
  k: string;
  subs?: RichSubs;
  /** English text used when the key resolves to '' (tNew-style keys). */
  fallback?: string;
}

function render(nodes: readonly RichNode[], subs: RichSubs | undefined, prefix: string): ReactNode[] {
  return nodes.map((n, i): ReactNode => {
    const key = `${prefix}${i}`;
    if (n.type === 'text') return n.text;
    if (n.type === 'slot') {
      if (subs === undefined || !Object.hasOwn(subs, n.name)) return `{{${n.name}}}`;
      const v = subs[n.name];
      return isValidElement(v) ? cloneElement(v, { key }) : v;
    }
    const children = render(n.children, subs, `${key}.`);
    if (n.tag !== 'a') return createElement(n.tag, { key }, ...children);
    if (n.href === undefined) return createElement(Fragment, { key }, ...children);
    return createElement('a', { key, href: n.href, target: '_blank', rel: 'noopener noreferrer' }, ...children);
  });
}

export function T({ k, subs, fallback }: TProps): ReactElement | null {
  const raw = rawMessage(k) || fallback || '';
  if (raw === '') return null;
  return createElement(Fragment, null, ...render(parseRich(raw), subs, ''));
}

export interface LocaleInfo {
  uiLocale: string;          // raw `@@ui_locale` (or getUILanguage())
  language: string;          // lower-cased primary subtag
  dir: 'ltr' | 'rtl';
  lang: string;              // BCP 47 tag for <html lang>
}

export function getLocaleInfo(): LocaleInfo {
  let uiLocale = '';
  try { uiLocale = i18n.getMessage('@@ui_locale') || ''; } catch { /* empty */ }
  if (uiLocale === '') {
    try { uiLocale = i18n.getUILanguage() || ''; } catch { /* empty */ }
  }
  if (uiLocale === '') uiLocale = 'en';
  const language = uiLocale.split(/[-_]/)[0].toLowerCase();
  const dir = RTL_LANGUAGES.includes(language) ? 'rtl' : 'ltr';
  const lang = SHIPPED_LANGUAGES.includes(language) ? uiLocale.replace(/_/g, '-') : 'en';
  return { uiLocale, language, dir, lang };
}

export function initDocumentLocale(doc: Document = document): LocaleInfo {
  const info = getLocaleInfo();
  doc.documentElement.setAttribute('dir', info.dir);
  doc.documentElement.setAttribute('lang', info.lang);
  doc.body?.setAttribute('dir', info.dir);           // upstream sets body[dir], i18n.js:39-44
  return info;
}

## Appendix B. Script used for the "longest" columns

Run with `node longest.mjs [key …]` (Node 22 or later; the numbers in this
document were produced with Node 26.8.2). It only reads `PRISTINE/_locales`
and prints one JSON line per key. Its output for all 116 keys was compared
field by field with the tables above (0 differences).

```js
import fs from 'node:fs';
const LOC = 'build/pristine/safari/_locales';
const locales = fs.readdirSync(LOC).filter(l => fs.existsSync(`${LOC}/${l}/messages.json`)).sort();
const msgs = Object.fromEntries(locales.map(l =>
  [l, JSON.parse(fs.readFileSync(`${LOC}/${l}/messages.json`, 'utf8'))]));
const seg = new Intl.Segmenter(undefined, { granularity: 'grapheme' });
const g = s => [...seg.segment(s)].length;
const keys = process.argv.length > 2 ? process.argv.slice(2) : Object.keys(msgs.en);
for (const k of keys) {
  const rows = locales.map(l => ({ l, s: (msgs[l][k]?.message ?? '').trim() }));
  const max = Math.max(...rows.map(r => r.s.length));
  const winners = rows.filter(r => r.s.length === max);          // every locale tied for longest
  const u = winners.find(r => r.l === 'en')                       // show English when it ties,
    ?? winners.reduce((a, b) => (g(b.s) > g(a.s) ? b : a));       // else the tied text with most clusters
  const c = rows.reduce((a, b) => (g(b.s) > g(a.s) ? b : a));     // most grapheme clusters
  console.log(JSON.stringify({
    key: k, en: msgs.en[k].message.trim().length,
    longest: { locale: u.l, ties: winners.length - 1, utf16: max, graphemes: g(u.s), text: u.s },
    mostGraphemes: { locale: c.l, graphemes: g(c.s), utf16: c.s.length },
  }));
}
```
